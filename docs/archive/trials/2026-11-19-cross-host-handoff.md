# 跨工具接手实测 · Continuity 3.9.4

2026-11-19，在 Windows 11 上用两个独立工具接力处理一个合成项目。发起方先完成标签格式化，随后收到改口，撤回拟上传的方案，只允许下一位生成本地交付文件。接手方得到的唯一用户消息是「继续」。

## 测试条件

- 新装路径从 3.9.4 候选 ZIP 解压。升级路径从公开的 3.9.3 ZIP 解压，发起方在旧版上工作并封存，然后才升级。两边都关闭聊天导入和复制。接手方使用新会话，上一工具的会话和测试记录保存在项目以外。
- `approved/payload.txt` 是获认可的文件，`build/payload.txt` 初始为同名旧稿。两份原始产品测试和获认可文件的 SHA-256 在发起方动手前固定。回执 `approval-A` 记录认可的内容摘要。每个试验项目使用自己的内容和摘要。
- 第一项任务由 Kimi Code 2.4.1 完成，并通过 `python -m unittest test_format`。第二次给 Kimi 的消息只要求登记新的授权、保留证据并交接。交接前独立运行 `python -m unittest test_delivery` 和 `ws receipt check T2`，两者都应失败。此时接手方确实还有工作要做。
- 接手方需实现 `deliver.py`、生成本地文件、运行原有的 `python -m unittest test_delivery` 并封存。复核者重新运行两份原测试、核对文件摘要与原回执、检查任务的验收证据和 `ws check --ready`。模型的总结单独保留。
